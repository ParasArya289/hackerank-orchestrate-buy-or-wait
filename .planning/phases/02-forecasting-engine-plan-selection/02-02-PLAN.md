<objective>
Turn a request's forecast results (amount_safe_to_pay, earliest_date_for_full_payment) plus the user's payment preferences and request_payment_options.csv rows into a ranked set of eligible payment plans, select the single best plan per the documented 6-step precedence, and derive any required spending changes — including recomputing safety with those spending changes simulated, so that a plan that is only safe after stopping/reducing a recurring flexible expense is correctly detected and ranked.

Purpose: This is the decision logic that turns "what's financially safe" into "what should the user actually do" (ROADMAP Phase 2 goal, problem_statement.md "Choosing Between Safe Plans"). It must correctly handle the general mechanism `dataset/sample_requests.csv` `request_06` illustrates — a `full_payment` that is only reachable after a spending change — even though this plan does not hardcode request_06's exact numbers (see Known Divergence note below).
